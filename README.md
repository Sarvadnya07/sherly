## 📖 Overview

**Sherly AI is a production-grade, desktop-native, voice-first AI developer copilot and local development orchestrator** designed for hands-free interaction with your codebase.

Unlike conventional cloud-dependent chat interfaces, Sherly bridges the gap between natural-language intent and safe, deterministic system execution.

### What Sherly Does

* **Voice & Text Interaction**: Real-time speech transcription via `faster-whisper` and offline text-to-speech synthesis via `pyttsx3`.
* **Deterministic Intent Routing**: Known developer commands run via deterministic routing in < 5ms without AI latency or cloud dependencies.
* **Autonomous Diagnostic & Self-Healing Loop**: Automatically executes project test/run commands, captures runtime tracebacks, retrieves relevant context, and drafts multi-file code fixes.
* **Human-in-the-Loop Patch Previews**: Displays visual diffs with confidence scoring and requires explicit developer confirmation (`approve <id>`) before any file modification.
* **Pre-State Atomic Backups & Undo**: Automatically snapshots previous file states into `backups/` and enables instant reversal via `undo` / `undo last action`.
* **Zero-Trust Command Security**: Strict allowlisting (`ALLOWED_PREFIXES`), argument tokenization via `shlex.split()`, `shell=False` execution, and complete elimination of `os.system()`.
* **Model Orchestration**: Auto-resolves local Ollama models (`qwen2.5-coder:3b` default) with single-model VRAM locking, idle auto-unloading (120s TTL), circuit breakers, and optional cloud fallbacks (OpenAI, Gemini, Groq).
* **Workspace & File Safety**: API path containment (`_get_safe_target()`) preventing directory traversal, streaming upload bounds (10 MB limit), and SSRF protection (`core/network_security.py`).
* **Multi-Interface Architecture**: Modern React 18 + Vite developer workspace, PySide6 desktop HUD with system tray integration, and headless FastAPI REST/WebSocket server.

## 🎯 Why Sherly Exists

Modern AI coding assistants often suffer from key architectural pitfalls:

1. **Unchecked Command Execution**: Blindly executing terminal commands generated by LLMs risks catastrophic filesystem and environment damage.
2. **Cloud Source Leaks**: Sending proprietary codebases to remote third-party APIs for routine searches or basic file explanations.
3. **No Safety Previews**: Silently overwriting source code without giving the developer a chance to review visual diffs or resolve base conflicts.
4. **Irreversible Modifications**: Lacking an undo engine or file snapshot mechanism when an automated fix introduces new bugs.
5. **High Latency & Resource Waste**: Invoking multi-billion parameter LLMs for routine tasks (e.g., opening applications, running tests, listing files) that can be handled deterministically.

### The Sherly Solution

```text
Deterministic Safety First ──→ Human Approval Boundary ──→ Atomic Reversibility ──→ Local LLM Last Resort
```

### The 6 Architecture Pillars

| Pillar | Layer | Responsibility & Implementation |
| :--- | :--- | :--- |
| **Pillar 1** | **Input Layer** | Input sanitization, length caps, debounce, and regex-based prompt injection detection (`input_validator.py`). |
| **Pillar 2** | **Execution Layer** | Rule-based deterministic routing (< 5ms) for known developer actions; LLMs invoked only for complex intents. |
| **Pillar 3** | **AI Layer** | Model lifecycle management (`model_manager.py`), active single-model lock, idle VRAM unloader (120s TTL), circuit breakers (`pybreaker`), and Ollama `/api/chat` integration. |
| **Pillar 4** | **System Layer** | Whitelisted command execution (`ALLOWED_PREFIXES`), argument vector tokenization (`shlex.split`), `shell=False`, and zero `os.system` invocations. |
| **Pillar 5** | **Control Layer** | 4-tier risk classification (`SAFE`, `CONFIRM`, `DANGEROUS`, `BLOCKED`) with thread-safe human approval gates (`safety_guard.py`). |
| **Pillar 6** | **Runtime Layer** | Thread-safe task queue (`core/task_queue.py`), pre-write conflict detection (`tools/preview.py`), atomic file writes, and persistent SQLite history. |

## 🚀 Key Features

### 1. 🎙️ Voice-Native Local Workflow
* Hands-free local speech-to-text powered by `faster-whisper` and offline text-to-speech with `pyttsx3`.
* Global hotkey trigger (`Ctrl + Shift + L`) and microphone toggle in the desktop UI.
* Wake-word detection powered by `pvporcupine` using the canonical `PVPORCUPINE_ACCESS_KEY` environment variable.

### 2. 🛡️ Multi-Tier Safety & Human-in-the-Loop Approval
* **SAFE**: Read-only queries (e.g., explaining code, listing directory contents) execute immediately.
* **CONFIRM**: State-modifying operations (e.g., writing files, applying code patches, installing packages) generate an approval ticket with a 120-second TTL.
* **DANGEROUS / BLOCKED**: Destructive operations (e.g., `rm -rf`, `format`, `del /s`, registry modifications) are blocked unconditionally.

### 3. 🔍 Git-Style Visual Patch Previews
* Multi-file unified diff generator (`tools/preview.py`) displaying additions (`➕`), deletions (`➖`), target filenames, confidence scores, and rationale.
* Pre-write base verification: Checks whether target files were modified externally before applying changes to prevent accidental overwrites.

### 4. ↩️ Atomic Undo & Action History
* Automatically snapshots previous file contents to `backups/` before applying modifications.
* Revert supported operations instantly via voice or text:
  ```text
  undo
  undo last action
  ```
* Review complete persistent operation history:
  ```text
  show action history
  ```

### 5. 🩹 Self-Healing Development Loop
Automates error resolution while keeping you in complete control:
1. **Run**: Executes project commands or test suites through the policy-controlled executor.
2. **Capture**: Intercepts return codes, stderr, and tracebacks.
3. **Analyze**: Queries local/cloud LLMs with project context to diagnose the root cause.
4. **Draft Fix**: Produces structured multi-file replacement code.
5. **Preview**: Displays an inline diff with action ID (`approve <id>`).
6. **Apply & Verify**: Upon approval, writes changes atomically and re-runs the project to confirm the fix.

### 6. 🤖 Specialized Agent Orchestration
* **CoderAgent**: Syntax inspection, code debugging, and multi-file patch generation (`agents/coder_agent.py`).
* **SystemAgent**: Safe desktop and OS navigation gated through `safe_exec` (`agents/system_agent.py`).
* **BrowserAgent**: Autonomous web research and DOM automation using Playwright (`agents/browser_agent.py`, `agents/playwright_agent.py`).

## 🔐 Security Architecture & Hardening

Sherly is built under a **zero-trust execution model**:

| Security Control | Implementation | Protection |
| :--- | :--- | :--- |
| **Command Execution** | `shlex.split()` + `shell=False` | Eliminates shell metacharacter injection (`&`, `;`, `\|`, `\n`) |
| **System Calls** | 0 `os.system()` calls across the repository | Prevents unquoted string evaluation in shell environments |
| **API Authentication** | `secrets.compare_digest(provided, configured)` | Prevents timing attacks; fails closed if `SHERLY_REMOTE_API_KEY` is unset |
| **Network & SSRF** | Centralized `core/network_security.py` validator | Rejects non-HTTP/HTTPS schemes, embedded credentials, private IPs, loopback, metadata services |
| **Path Traversal** | Canonical `_get_safe_target()` with `relative_to(workspace_root)` | Prevents escaping the project directory boundary (`../`) |
| **File Uploads** | Bounded streaming reads (`min(1MB, limit - total)`), 10 MB maximum | Defends against memory exhaustion (DoS) and oversized payloads |
| **Secret Management** | `config.json` untracked in git; `PVPORCUPINE_ACCESS_KEY` canonicalized | Prevents accidental credential exposure in commits |
| **Frontend Secrets** | `sessionStorage` session-scoped prompting in `remote_ui/index.html` | Zero hardcoded server API keys in client-side HTML/JavaScript |

## ⚡ Performance & Reliability

| Feature | Implementation | Engineering Benefit |
| :--- | :--- | :--- |
| **Deterministic Fast-Path** | In-memory `COMMAND_MAP` (< 5ms execution) | Bypasses LLM inference for common OS & workspace shortcuts |
| **Active-Model Lock** | `threading.Lock` in `model_manager.py` | Prevents concurrent model loading and memory/VRAM thrashing |
| **Idle VRAM Unloader** | Background daemon thread (120s idle threshold) | Releases GPU memory via Ollama `keep_alive: 0` |
| **Circuit Breakers** | `pybreaker` with 3-failure threshold & 30s reset | Protects against cascading failures when cloud providers are down |
| **Bounded History** | Sliding window context truncation (max 10 messages) | Prevents context window overflows and reduces token latency |
| **FastAPI Lifespan** | `@asynccontextmanager async def lifespan(app)` | Gracefully resolves models on startup and releases audio on shutdown with 0 warnings |

## 🚀 Installation & Setup

### Prerequisites

* **Python 3.10+** (Python 3.13 recommended)
* **Node.js 18+ & npm** (Node 20 LTS recommended)
* **Git**
* **Ollama** (for local privacy-first LLM inference)
* Microphone access (for voice interaction)

### 1. Clone the Repository

```bash
git clone https://github.com/Sarvadnya07/sherly.git
cd sherly
```

### 2. Set Up Python Virtual Environment

#### Windows (PowerShell)
```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

#### macOS / Linux
```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Install Python Dependencies

```bash
pip install --upgrade pip
pip install -r requirements.txt
```

### 4. Build Frontend Assets

```bash
cd frontend
npm install
npm run build
cd ..
```

### 5. Configure Environment Variables

Create your local `.env` configuration from the template:

#### Windows
```powershell
copy .env.example .env
```

#### macOS / Linux
```bash
cp .env.example .env
```

Edit `.env` to configure optional keys:
```ini
# Optional Cloud LLM API Keys (Leave blank to use local Ollama exclusively)
OPENAI_API_KEY=your_openai_api_key_here
GEMINI_API_KEY=your_gemini_api_key_here
GROQ_API_KEY=your_groq_api_key_here

# Remote API Server Authentication
SHERLY_REMOTE_API_KEY=your_secure_remote_api_key_here

# Picovoice Wake-Word AccessKey (Optional, from console.picovoice.ai)
PVPORCUPINE_ACCESS_KEY=your_picovoice_access_key_here
```

### 6. Pull the Recommended Local Model

```bash
ollama pull qwen2.5-coder:3b
```

## 💻 Running Sherly

### Option A: Native Desktop App (PySide6 HUD)
Launches the native dark-themed desktop interface with integrated voice recognition and system tray controls:

```bash
python main.py
```

### Option B: FastAPI Backend & React Workspace
Start the backend server on `127.0.0.1:8000`:

```bash
python -m backend.main
```

Then launch the Vite development server in another terminal:
```bash
cd frontend
npm run dev
```
Open `http://localhost:5173` in your browser.

### Option C: Remote Assistant API & PWA
Start the remote access server on `127.0.0.1:5000`:

```bash
uvicorn remote_api.server:app --host 127.0.0.1 --port 5000
```
Navigate to `http://localhost:5000` to access the lightweight remote web interface.
